# 侧边栏会话双层置顶与项目归档设计方案

> 状态：设计草案，待评审；本轮不实现功能。
>
> 日期：2026-11-02
>
> 文档版本：0.1.1
>
> 范围：Agent 模式的项目与会话侧边栏，普通 Chat 对话不在本期调整范围内。

## 1. 需求结论与评审边界

### 1.1 用户已确认

1. 区分“项目内置顶”和“全局置顶”两个独立状态。
2. 会话菜单的“置顶”只把会话放到所属项目会话列表最上方，不直接移到独立区域。
3. 多个项目内置顶会话不需要拖拽排序，只需要置顶、取消置顶。
4. 只有已经项目内置顶的会话，才能长按拖拽到侧边栏顶部的全局置顶区域。
5. 项目可以归档；归档时，该项目下所有会话也标记为已归档。
6. 默认项目不允许归档；归档当前项目后，自动切换到默认项目或其他可用项目。
7. 保留统一的“已归档”按钮，进入后分为“已归档项目”和“已归档会话”两个区域。
8. 已归档项目下的会话不能单独激活，必须先激活项目。
9. 项目归档不是删除，后续仍需恢复项目继续开发。

### 1.2 本方案建议，尚待评审

以下不是用户已确认的细节。后续章节按这些建议展开，实现前须按评审结论定稿。

| 事项 | 建议行为 | 原因 |
| --- | --- | --- |
| 全局区是否重复显示 | 仅在顶部展示，原项目不重复显示；保留 `workspaceId` | 避免同一会话出现两行，不改变项目归属 |
| 移出全局区 | 回到原项目并保留项目内置顶 | 移除全局快捷入口不等于取消项目内置顶 |
| 多个置顶会话排序 | 项目内和全局区都按 `updatedAt` 降序 | 不增加手动顺序数据和排序交互 |
| 恢复项目 | 只恢复项目本身，不批量恢复会话；之后按需恢复会话 | 明确“先激活项目，再激活会话”，避免旧会话全部回到侧栏 |
| 归档时置顶标记 | 清除项目内及全局置顶，恢复时不重新置顶 | 延续现有会话归档取消置顶的规则 |
| 运行中项目归档 | 有运行、启动占用或待发送消息时拒绝归档，提示先停止并处理队列 | 不静默中断 Agent，不增加停止后恢复任务的复杂流程 |
| 归档项目的自动任务 | 保留任务配置与启用偏好，归档期间跳过执行；恢复后参与未来正常触发 | 不让后台任务唤醒归档项目，不补跑错过的触发 |
| 历史置顶数据 | 旧 `pinned` 作为项目内置顶，不自动进入全局区 | 普通置顶留在项目内，全局区由用户重新选择 |
| 归档历史保留 | 项目仍归档时，其会话不参与按归档期限清理正文 | 防止项目元数据还在、历史记录却被清理 |

### 1.3 本期不做

- 不新增数据库、第三方拖拽依赖、通用收藏系统或多级项目分组。
- 不支持置顶会话的手动排序，不通过拖拽改变项目归属。
- 不增加自动归档项目、定时恢复、归档前状态快照或批量恢复选项。
- 不改变 Agent cwd、项目根目录授权、Skills/MCP 所有权和 Pi 会话恢复语义。
- 不整体重写侧边栏、普通 Chat 置顶和现有项目排序。

## 3. 两层置顶交互

### 3.1 活跃视图

```text
全局置顶
  会话 A                         项目甲

项目
  项目甲
    会话 B                       [项目内置顶]
    会话 C                       [项目内置顶]
    会话 D                       [运行中]
    会话 E
  项目乙
    会话 F

已归档（2 个项目，18 个会话）
```

- 全局行显示来源项目，点击打开原会话，上下文仍跟随 `workspaceId`。
- 全局置顶不复制会话、不移动文件、不迁移项目，只改变侧栏展示位置。
- 某项目仅剩全局置顶会话时，显示“会话已显示在全局置顶区”，不误导为会话丢失。
- 复用既有主题变量、菜单 primitives、行密度与父子会话树。

### 3.2 项目内置顶

菜单改为“在项目内置顶 / 取消项目内置顶”，避免继续用含糊的“置顶会话”。

项目展开后的根会话顺序：

1. 所有项目内置顶但未全局置顶的会话树，按 `updatedAt` 降序。
2. 其余会话保留现有运行/阻塞优先、近期预览、显示更多和当前会话可见规则。

置顶会话不受近期窗口及普通预览数量限制，不挤占普通会话预览名额，也不计入隐藏会话数量。折叠项目仍隐藏其全部会话，不因置顶强制展开。

父子会话继续按现有树组织：母会话置顶保留是否同步子会话的选择；单独置顶子会话保留既有入口。全局置顶母会话时，子会话跟随树展示，不批量写子会话的全局标记。已独立全局置顶的子会话不再同时出现在母会话树下，避免重复行。

### 3.3 长按拖入全局区

1. 仅活跃项目下、未归档且已项目内置顶的会话可开始拖拽。
2. 左键长按会话主体约 300ms 后进入可拖状态；提前松开仍为普通点击，提前明显移动取消长按。菜单、归档按钮、输入框和展开按钮不触发拖拽。
3. 复用原生 HTML Drag and Drop，不新增依赖。会话使用独立 payload 类型，与项目拖拽区分。
4. 拖拽期间，侧栏顶部提供始终可达的全局放置目标；全局区为空或列表已滚动时也能首次放入。
5. 合法目标高亮，释放后请求主进程设置全局置顶；主进程重新检查项目、归档及项目内置顶状态。
6. 保存成功才改变展示位置；失败保留原位置并提示。拖至无效位置、Escape、拖出窗口均不改持久状态。

未置顶会话不能因拖向顶部而自动置顶。为兼容键盘操作，已项目内置顶会话菜单可提供“移至全局置顶区”，调用同一接口并执行同样的资格校验，不新增快捷键。

### 3.4 移回项目

- 菜单“移回项目内置顶”只清除全局标记，保留项目内置顶。
- 允许拖回原所属项目头部；原项目折叠时接收放置并展开，便于确认结果。
- 拖到其他项目无效，不暗中迁移项目。
- 全局会话若选择“取消项目内置顶”，同时清除全局标记，回到普通项目列表。
- 通过既有迁移功能换项目时，移出全局区、保留项目内置顶；迁移目标必须活跃。

## 4. 项目归档与恢复

### 4.1 入口与确认

真实项目菜单新增“归档项目”，与删除分开。默认项目禁用并提示“默认项目不能归档”；“定时任务”合成组不是真实项目，不提供该操作。

确认文案：

> 归档「项目甲」及其全部会话？项目将从活跃列表隐藏，相关标签页将关闭。项目文件、会话记录和配置保留，可在“已归档”中恢复。

有关联自动任务时补充说明归档期间任务不执行。有忙碌会话时提示“请先停止项目中的 Agent 并处理待发送消息”，本次不改变状态。

### 4.2 归档结果

- 项目设置 `archived = true`。
- 主进程按 `workspaceId` 从完整索引收集全部会话，包括普通会话、全局置顶、已有归档、草稿、委派子会话、探索分支、自动任务会话；不能仅处理 renderer 当前加载的会话。
- 全部设置 `archived = true`，清除两层置顶；草稿转为普通归档会话，确保之后有恢复入口。
- 从活跃项目列表、收起态项目切换器、全局置顶和最近入口隐藏该项目及会话；自动任务合成组也不能泄漏它们。
- 关闭相关 Agent 与预览标签页，清理临时 UI 状态，但不删除项目文件、JSONL、Pi artifact、workbench、MCP/Skills、记忆或绑定配置。
- 归档当前项目时最终选择默认项目并更新持久设置；关闭标签后的同步副作用不能再把当前指针切回归档项目。
- 保留项目在完整项目数组的位置；活跃项目排序不能把归档项目丢弃或全部挪到末尾。

### 4.3 统一归档视图

```text
已归档

已归档项目（2）
  项目甲                         [恢复项目]
  项目乙                         [恢复项目]

已归档会话（18）
  项目甲 · 项目已归档
    会话 A                       [先恢复项目]
    会话 B                       [先恢复项目]
  项目丙
    会话 C                       [恢复会话]

返回活跃会话
```

- 一个页面两个区域，不新增第二个归档按钮或独立页面路由。
- 项目区域只列真实归档项目，包括空项目，不在此区域重复展开会话。
- 会话区域继续按项目分组；所属项目已归档则显示状态和“先恢复项目”，不复制会话数据。
- 两个区域都有独立标题和空状态。项目数与会话数分别显示，不相加为模糊总数。
- 即使归档会话数为零，只要有归档项目，统一入口仍然可见。
- 归档会话元数据仍按需加载，不在活跃视图额外加载全部历史正文。
- 点击“先恢复项目”定位或打开项目恢复确认，不自动连带恢复该会话。

### 4.4 恢复顺序

按本方案建议：

1. 恢复项目只设置项目 `archived = false`，回到原项目顺序，不自动打开会话或立即执行自动任务。
2. 会话仍留在已归档会话区域，此时可以逐个“恢复会话”。
3. 恢复会话后回到所属项目，沿用现有母会话恢复子会话规则，不恢复归档前置顶。

项目恢复确认明确提示“恢复项目后，会话仍保留在已归档列表，可按需恢复”。

恢复会话、置顶归档会话以解归档、从搜索继续发送等入口均须先检查项目。归档项目不能被隐式恢复或设为当前项目。历史可保留只读查看，但发送、新建、fork/委派执行、迁移入该项目要求先恢复项目。

## 5. 最小数据模型与存量处理

沿用已有索引，不新增配置文件。在 `packages/shared/src/types/agent.ts` 的既有接口中增补字段：

```ts
export interface AgentWorkspace {
  // 既有字段保持不变。
  archived?: boolean
}

export interface AgentSessionMeta {
  // 既有字段保持不变。
  pinned?: boolean       // 所属项目内置顶
  globalPinned?: boolean // 在跨项目全局区展示
  archived?: boolean
}
```

两种操作独立，但全局置顶具有项目内置顶资格约束：

| 状态 | pinned | globalPinned | 位置 |
| --- | --- | --- | --- |
| 普通活跃 | false | false | 所属项目普通列表 |
| 项目内置顶 | true | false | 所属项目置顶列表 |
| 全局置顶 | true | true | 全局区，仍属原项目 |
| 会话已归档 | false | false | 已归档会话 |
| 项目已归档 | false | false | 项目与全部会话均在归档视图 |

约束：`globalPinned => pinned && !session.archived && !workspace.archived`。取消项目内置顶、归档会话或归档项目，都同时清除全局标记。

- 旧项目缺少 `archived` 等价于活跃；旧会话缺少 `globalPinned` 等价于非全局置顶。
- 旧 `pinned = true` 在新版作为项目内置顶，不自动生成全局标记。
- 不需要全量重写旧数据或搬移文件，不仅为新增可选字段升级索引 schema version。
- 不增加 `pinOrder`、全局 ID 数组、归档批次、归档前快照或永久保留字段。
- 无真实项目归属的遗留会话保留现有展示，不猜测写入 `workspaceId`；确定归属前不能新增全局置顶。
- “定时任务”合成组保留既有来源关系；其置顶可留在原合成组内，但该组不是本期“项目内置顶后拖入全局”的新增入口，不因置顶改写项目归属。

## 6. 主进程、IPC 与状态流

### 6.1 明确意图接口

拟新增 `SET_GLOBAL_PIN` 与 `SET_WORKSPACE_ARCHIVED` 通道及 preload 方法，命名实施时与既有风格对齐：

```ts
export interface SetAgentSessionGlobalPinnedInput {
  sessionId: string
  globalPinned: boolean
}

export interface SetAgentWorkspaceArchivedInput {
  workspaceId: string
  archived: boolean
}

export interface SetAgentWorkspaceArchivedResult {
  workspace: AgentWorkspace
  affectedSessionIds: string[]
}
```

使用显式布尔值而非 toggle，重复提交不反转状态。返回受影响 ID 供 renderer 关闭标签并刷新，不返回正文。

现有 `TOGGLE_PIN` 改为项目内语义，`TOGGLE_ARCHIVE` 增加项目守卫；保留现有父子级联选择，主进程保证所有写入遵守数据约束。

四层契约同步检查：共享类型/常量与导出、`main/ipc.ts` handler、`preload/index.ts` 类型及 bridge、renderer 调用/错误/状态处理。

### 6.2 项目归档保存流程

1. 校验项目存在、非默认，检查运行/启动占用/待发送队列；无效不写任何归档状态。
2. 从完整会话索引收集会话，构造归档后数据，一次批量写会话索引，不由 renderer 循环 toggle。
3. 再写项目归档字段；两次写入间不插异步等待，避免普通事件中途创建会话。
4. 成功后返回结果，刷新项目与会话/计数，关闭标签，再确定最终可用项目。

每个 JSON 使用 `safe-file.ts` 原子写入，但这不等于跨文件事务。若会话索引成功、项目索引失败，提示“会话已归档，项目归档失败，请重试”，刷新真实状态，不声称整体成功或虚假回滚。再次设置同一状态可安全重试；管理器缓存不能在写盘失败后保留未落盘的成功状态。

本期不引入跨文件事务日志或恢复引擎，覆盖正常保存与明确的部分失败反馈即可。

### 6.3 防止其他入口绕过归档

| 入口 | 必须处理 |
| --- | --- |
| 新建、恢复、置顶会话 | 主进程检查目标项目；归档项目先恢复 |
| Agent 发送、启动占用、队列消费 | 启动边界再次检查，不只禁用侧栏按钮 |
| 标题、模型、完成状态等更新 | 可保留必要元数据更新，但不得顺带解归档项目下的会话 |
| 消息追加与后台回调 | 不自动解归档，不丢弃合法已产生的历史记录 |
| Automation、Collaboration、IM | 复用项目状态检查，不能新建或复用会话唤醒归档项目 |
| 搜索、最近入口、Tab、托盘 | 不作为活跃入口；历史可只读，恢复操作先检查项目 |
| 当前项目设置与启动恢复 | 如指向归档项目则选默认项目，保留完整项目元数据供历史解析 |
| 存储清理 | 仍归档项目的正文不参与期限清理，归档资源不被视为孤儿 |

归档不调用设置删除墓碑的 `stopAgentAndDrain()`，不删除绑定。自动任务不改 disabled 偏好，仅在归档期间跳过执行并展示原因，恢复后不补跑。

历史保留建议的边界：项目恢复后，尚未恢复的会话重新适用原有归档期限清理规则，应在恢复确认中告知；本期不新增永久保留标记。

### 6.4 renderer 组织

- `agentWorkspacesAtom` 保留全部项目，用 Jotai 派生活跃和归档列表，不能直接替换成活跃列表导致历史名称丢失。
- 活跃切换器、Todo/Automation 项目选择、迁移目标只列活跃项目；已有归档关联显示“项目已归档”，不能误标已删除。
- 全局区读取 `globalPinned`；项目列表排除 `globalPinned`，不再排除所有 `pinned`。
- 必要分组/置顶分区纯函数放在既有 `agent-session-list.ts` 附近并直接测试，不新增通用侧栏状态机。
- 手势和单次保存状态局部管理；持久数据经 Jotai 与主进程返回值同步，不另存置顶缓存。
- Rail 不整体重写运行状态优先规则，但过滤归档项目；全局快捷入口不能因切换当前项目而失去可达性。
- 项目拖拽只重排活跃项目所在槽位，保留归档项目位置；合成任务组索引按活跃展示列表计算。

## 8. BDD 验收与检查

以下是待实现的验收场景，本轮没有编写或运行这些功能测试。

| Given | When | Then |
| --- | --- | --- |
| 项目甲中普通会话 A | 选择项目内置顶 | A 在项目甲最上方，不进入全局区 |
| 多个置顶、旧会话、运行会话与普通会话 | 展开项目 | 置顶全部在前，不受近期窗口限制；普通预览额度不变 |
| A 未置顶 | 拖向全局区或直接调用新增 IPC | 拒绝，不能自动补项目内置顶 |
| A 已项目内置顶 | 长按拖入全局区 | 两字段均 true，原项目不重复，来源信息保留 |
| 全局区为空，项目列表已滚动 | 拖动合法会话 | 顶部目标可达，可完成第一次放入 |
| A 已全局置顶 | 移回原项目 | 全局 false、项目内 true；拖往其他项目无效 |
| A 已全局置顶 | 取消项目内置顶或归档 A | 清除两层标记，不残留全局行 |
| 母/子会话独立或随树展示 | 置顶、移入全局、移出全局 | 同一会话只出现一次，级联选择与树状态仍正确 |
| 正在拖拽会话 | Escape、放错位置或保存失败 | 无持久状态改变，项目顺序不受影响 |
| 默认项目 | UI 或 IPC 请求归档 | 拒绝，任何会话状态均不改变 |
| 项目含活跃、草稿、已归档、委派、探索、自动任务会话 | 归档项目 | 完整索引内全部归档，清除两层置顶，其他项目不变 |
| 当前项目有打开标签但无忙碌会话 | 归档项目 | 相关标签关闭，最终当前项目为默认项目，重启仍一致 |
| 项目有运行/预检占用/队列 | 归档项目 | 拒绝，不中断或删除运行，不部分归档 |
| 空项目已归档、归档会话数为零 | 查看侧栏底部 | 归档入口仍可见，项目可恢复 |
| 项目与其会话均已归档 | 恢复或置顶会话 | 拒绝并引导先恢复项目；直接 IPC 也不能绕过 |
| 项目已归档 | 修改标题、后台回调或任务触发 | 会话不被自动解归档，项目不被唤醒 |
| 已归档项目 | 先恢复项目再恢复会话 | 项目恢复不批量激活会话；恢复会话后可正常开发 |
| 开启归档期限清理 | 清理仍归档项目的旧会话 | JSONL 保留，项目未被当成孤儿 |
| 两个索引的第二次写入失败 | 归档项目 | 返回明确部分失败，刷新真实状态，可重试 |
| 旧数据仅有 pinned，无新增字段 | 升级后打开 | 旧置顶回项目内，旧项目活跃，无需搬移文件 |
| 活跃与归档项目混合 | 拖拽活跃项目后恢复归档项目 | 顺序稳定，归档条目不丢失，合成组索引正确 |

最小相关测试完成后运行 `bun run typecheck`。现有 `agent-session-manager.test.ts`、`collapsed-agent-rail.test.ts` 可扩展；项目归档、分组与清理过滤按职责补测试文件，不为测试重构无关模块。

人工检查覆盖：深浅主题、键盘菜单、普通点击不误拖、首次空全局区、长列表滚动后拖放、保存中禁用、失败提示、归档计数、重启持久化，以及现有项目拖拽/新建/迁移/父子会话不回归。仅单元测试通过不等于 Electron 长按交互验收完成。
